# 기능이 연결되는 세 가지 업무 사례

최신 v2 코드의 연결 관계를 가상의 업무 상황으로 설명합니다. 실제 계약·고객·제품 번호는 사용하지 않습니다.

## 사례 1. 영업 품목이 생산과 설치까지 이어지는 과정

**상황:** 담당자가 고객에게 제품 여러 대를 납품해야 한다.

1. 영업건에 제품·옵션·수량을 등록하고 견적·계약 문서를 연결한다.
2. 계약 품목을 생산요청에 연결해 생산팀이 납기·납품처·수량을 확인한다.
3. 생산완료 시 수량에 맞는 S/N과 BOM·재고를 검사한다.
4. 트랜잭션 안에서 구성품 재고를 차감하고 완제품 재고·S/N·요청 상태를 반영한다.
5. 시리얼 화면에서 제품과 연결 유심을 확인한다.
6. 설치 완료 정보의 관련 S/N으로 유심 설치일·담당자를 갱신한다.

**핵심:** 영업 화면에서 시작한 일이 생산 상태만 바꾸고 끝나지 않고 제품 식별과 현장 관리까지 연결된다.

**코드:** `sales_log.php` → `production_request.php` → `sn_search.php` → `service_lib.php::syncUsimInstall`.

## 사례 2. 계산서와 입금을 분리해 미수금을 확인하는 과정

**상황:** 한 계약의 청구 금액을 여러 번에 나누어 받는다.

1. 영업건에 계산서 발행 예정 또는 월별 정기 일정을 등록한다.
2. 발행한 문서를 등록하고 해당 문서에 일시불/분할 입금 계획을 만든다.
3. 분할 금액 합계가 문서 금액과 맞는지 검사한다.
4. 실제 입금은 계획과 별도로 날짜·금액을 누적한다.
5. 문서별 잔액과 국내/해외 전체 미수·임박 일정을 확인한다.
6. 취소 시 미입금 계획은 정리하고 기입금 기록은 남겨 실제 받은 돈의 기록이 사라지지 않게 한다.

**핵심:** 계약 금액·청구·입금·미수 상태를 각각의 기록으로 분리한다. 외부 세금계산서 발행·은행 거래를 자동 실행하는 예제가 아니다.

**코드:** `createDocPlan`, `RECEIVE_DEAL_PAYMENT`, `CANCEL_DEAL_DOCUMENT`, `invoice_status.php`.

## 사례 3. 일하면서 남긴 기록이 회의자료가 되는 과정

**상황:** 메일로 요청을 받고 여러 부서가 처리해야 한다.

1. 메일 본문·첨부파일을 업무협조로 전달한다.
2. 업무협조의 담당자·상태·처리 이력을 남긴다.
3. 완료 내용과 화면에서 선택한 업무 항목을 Task로 이어간다.
4. Task를 개인 주간보고의 실적·계획에 사용한다.
5. 전사 주간보고를 취합한다. 영업회의는 계산서·입금·현장처리·A/S·대여 현황을 별도로 자동 취합하고 담당자의 현황·다음 할 일을 더한다.

**핵심:** 메일, 실행 업무, 보고서가 각각 별도의 메모로 끝나지 않도록 연결한다.

**코드:** `mail_detail.php`, `work_order.php`, `meeting_pin.php`, `weekly_report_*.php`, `weekly_sales_meeting.php`.
