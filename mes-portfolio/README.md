| 구분 | 내용 |
|---|---|
| 상태 | 운영을 전제로 개발·보완 중; 이번 검토는 저장소 코드·문서 기준 |

## System Architecture

```text
Browser
  ↓
자체 CSS/JavaScript + Fetch API
  ↓
PHP Web Application + Session
  ↓
PDO / Prepared Statement
  ↓
MySQL / MariaDB
```

여러 업무 테이블을 연결하는 구조로 사용자·권한, 제품·부품·BOM, 창고·재고·시리얼, 생산·불량, 업무·프로젝트, 주간보고, 고객·A/S 데이터를 관리합니다.

## Backend & Data Integrity

- PDO Prepared Statement로 SQL Injection 위험 감소
- `password_hash`, `password_verify` 기반 비밀번호 처리
- 로그인 CSRF 검증
- Session 기반 사용자 인증
- 재고·생산 데이터 변경 시 Transaction 적용
- 동시 수정 가능성이 있는 영역에서 `SELECT ... FOR UPDATE` 사용
- Git으로 기능 변경사항과 통합 과정 관리

트랜잭션과 행 잠금이 적용된 제조 영역은 프로젝트 공통 구현으로 확인했으며 개인 단독 성과로 주장하지 않습니다.

## 운영·배포 방식과 후속 검증

개발 문서상 로컬 수정 후 FTP로 배포하고, 배포한 최종본을 Git에 수동 동기화합니다. GitHub Actions 자동배포는 사용하지 않습니다. 따라서 저장소 최신 커밋만으로 실제 서버와의 완전한 일치를 보증하지 않습니다.

현재 기능을 공개용으로 정리하면서 다음 항목을 후속 검증 대상으로 구분합니다.

- 권한별 메뉴와 기능 접근 범위
- 입력 항목과 업무 상태 전환 흐름
- 제조·시리얼·고객·A/S 데이터 연결
- 예외 처리와 사용자 안내
- 테스트 데이터 정비
- 현장 사용자 피드백 반영
- 배포와 운영 안정화
