## 2. 프로젝트 배경

하천의 녹조·부유물 상태를 사람이 CCTV 화면으로 계속 확인하려면 많은 시간이 필요하고, 관찰자에 따라 판단 결과도 달라질 수 있습니다.

TOVNET-SEG는 CCTV 영상에서 수면의 조류 영역을 자동으로 분할하고 점유율을 정량화하여 다음 업무를 지원하는 시스템입니다.

- 수면 조류·부유 영역 자동 식별
- 영상 내 조류 점유율 계산
- 임계값 기반 이상 상태 판단
- 다중 CCTV 상태 모니터링
- 관제 플랫폼으로 탐지 결과 전송
- 분석 결과 영상 및 이벤트 이력 제공

## 4. 원개발 모델

### 모델 목적

일반적인 객체 검출처럼 대상의 사각형 위치만 찾는 것이 아니라, 각 픽셀이 조류인지 배경인지 분류하는 **Binary Semantic Segmentation** 모델입니다.

```text
입력: 고해상도 RGB CCTV 이미지
출력: 배경 0 / 조류 1의 픽셀 단위 마스크
```

### 모델 변화 과정

인수 문서에는 다음 모델을 비교·검토한 과정이 기록되어 있습니다.

| 단계 | 모델 | 검토 내용 |
|---|---|---|
| 초기 기준 모델 | DeepLabV3+ · ResNet50 | 분할 정확도 기준선 설정, 실시간 처리 속도 제약 확인 |
| 경량화 검토 | Fast-SCNN | 처리속도 향상 가능성 확인, 세밀한 경계 표현 한계 검토 |
| 최종 적용 | OneFormer · Swin-Large | 도메인 파인튜닝과 고해상도 분할 파이프라인 적용 |

### 데이터셋

인수 문서 기준으로 다음 데이터 구성이 기록되어 있습니다.

- RGB 원본 영상: 1,238장
- 픽셀 단위 이진 마스크: 1,238장
- 학습 데이터: 866장
- 검증 데이터: 248장
- 테스트 데이터: 124장
- 원본과 마스크의 파일명을 일치시켜 데이터 쌍 구성
- 학습·검증·테스트 사이의 이미지 중복을 방지하는 분할 방식

이 수치는 원개발 문서의 기록이며, 현재 별도의 재현시험을 통해 다시 검증할 대상입니다.

### 학습·추론 기술

- Python·PyTorch
- OneFormer for Universal Segmentation
- Swin Transformer Large 백본
- ADE20K 사전학습 가중치 활용
- 수면 조류 데이터 기반 파인튜닝
- BCE·Dice 계열 손실함수
- AdamW Optimizer
- Mixed Precision 추론
- IoU, F1-score, Pixel Accuracy 평가

## 5. 고해상도 추론 방식

### 기존 타일 추론

초기 방식은 고해상도 CCTV 영상을 작은 타일로 나누고, 각 타일을 추론한 뒤 다시 합치는 구조였습니다.

```text
고해상도 영상
   ↓ 분할
여러 개의 작은 타일
   ↓ 반복 추론
타일별 마스크
   ↓ 합성
전체 분할 결과
```

인수 문서에 기록된 문제:

- 이미지 한 장당 모델을 여러 번 호출
- GPU 커널 호출과 데이터 전송 증가
- 타일 경계에서 분할 결과가 끊기는 현상
- 겹치는 영역을 다시 합치는 후처리 비용
- 추론 및 스티칭 코드의 복잡도 증가

### Full Resolution 추론

이후 전체 영상을 한 번에 입력하는 방식으로 변경되었습니다.

```text
1920×1080 영상
      ↓ 입력 정렬을 위한 패딩
1920×1088 영상
      ↓ 단일 GPU 추론
전체 분할 마스크
      ↓ 패딩 영역 제거
1920×1080 결과
```

### 문서에 기록된 비교 결과

| 지표 | 타일 추론 | Full Resolution |
|---|---:|---:|
| 평균 지연시간 | 1,481ms | 646ms |
| mIoU | 0.3534 | 0.3820 |
| F1-score | 0.412 | 0.438 |
| Pixel Accuracy | 0.967 | 0.971 |
| GPU 모델 호출 | 이미지당 다수 | 이미지당 1회 |
| Full Resolution VRAM | - | 6.33GB |

> 해당 결과는 인수 문서에 기록된 원개발 측정값입니다. 평가 대상과 일부 수치가 문서 내에서 일관되지 않은 부분이 있어, 현재 개인 성과 또는 최종 검증 결과로 사용하지 않습니다.

## 6. 운영 시스템 구성

### 영상 수집

- RTSP 기반 CCTV 스트림 입력
- FFmpeg를 이용한 영상 디코딩
- NVIDIA 하드웨어 디코딩 사용 구조
- 스트림 연결 실패 시 재연결
- 오래된 프레임이 계속 쌓이지 않도록 최신 프레임 우선 처리

### AI 추론

- OneFormer 추론 엔진 클래스
- 여러 CCTV 프레임의 배치 처리
- GPU Mixed Precision 추론
- 전처리·추론·후처리 시간 측정
- 마스크와 조류 점유율 생성

### 이벤트 처리

- 점유율 임계값 기반 정상·이상 상태 판단
- 상태 변화가 반복되는 현상을 줄이기 위한 히스테리시스
- 동일 알림의 반복 발생을 제한하는 쿨다운
- 이벤트 결과와 스냅샷 저장

### 외부 시스템 연동

- MySQL: CCTV 정보와 운영 설정 관리
- Redis: 최신 분석 상태 캐시
- REST API: 관제 플랫폼에 탐지 결과 전달
- SQLite: 로컬 이벤트 기록
- Flask: 모니터링 웹 화면 및 영상 제공
- HLS·MJPEG: 분석 결과 스트리밍

## 8. 운영 장애 사례 분석

### 사례 1. RTSP 재연결 후 메모리 증가

```text
RTSP 연결 불안정
      ↓
스트림 재연결 반복
      ↓
처리하지 못한 프레임 누적
      ↓
메모리 사용량 증가
      ↓
운영체제의 프로세스 종료
```

검토한 대응 방향:

- 프레임 큐의 최대 크기 제한
- 오래된 프레임을 버리고 최신 프레임 우선 처리
- 추론 속도보다 빠른 입력을 자연스럽게 제한
- 스트림 종료 시 큐와 관련 자원 정리

### 사례 2. 모델 가중치 호환성

라이브러리 버전이 달라지면서 저장된 체크포인트의 키 이름과 현재 모델 구조가 일치하지 않는 문제가 기록되어 있습니다.

검토 항목:

- 실행환경 및 라이브러리 버전 고정
- 체크포인트 해시를 이용한 파일 무결성 확인
- Missing·Unexpected Key 목록 확인
- 기준 데이터에 대한 재현 평가 수행
- 모델을 정상적으로 불러오지 못한 상태에서 서비스를 시작하지 않도록 검증

### 사례 3. FFmpeg 프로세스 잔류

메인 Python 프로세스만 종료하면 자식 FFmpeg 프로세스가 남아 포트와 시스템 자원을 계속 사용할 수 있습니다.

검토 항목:

- 부모·자식 프로세스의 종료 순서 정의
- 정상 종료와 강제 종료 단계 구분
- HLS 임시파일 정리
- 재시작 전에 기존 프로세스와 포트 사용 여부 확인

## 10. 재현 및 검증 계획

인수 문서의 결과를 그대로 개인 성과로 사용하지 않고 다음 절차로 검증할 계획입니다.

```text
실행환경과 버전 고정
      ↓
체크포인트 무결성 확인
      ↓
평가 데이터 범위 확정
      ↓
기존 평가 스크립트 실행
      ↓
IoU·F1·Latency 재측정
      ↓
오탐·미탐 사례 시각화
      ↓
개선 전후 동일 조건 비교
```

검증 항목:

- Python·PyTorch·Transformers·CUDA 버전
- 사용 GPU 및 입력 해상도
- 평가 대상 이미지 목록
- 마스크 전처리와 임계값
- 워밍업 포함 여부와 지연시간 측정 방식
- 카메라별·환경별 성능

## 11. 기술적으로 배운 점

- 객체 검출과 Semantic Segmentation의 차이
- 픽셀 불균형 상황에서 Accuracy만으로 평가하면 안 되는 이유
- IoU와 F1-score를 함께 확인해야 하는 이유
- 높은 GPU 사용률이 곧 높은 처리속도를 의미하지 않는다는 점
- 실시간 영상 시스템에서 최신 프레임 우선 전략이 중요한 이유
- 모델 성능뿐 아니라 RTSP·큐·프로세스·API가 전체 서비스 품질을 결정한다는 점
- 연구 결과를 인수할 때 실행환경과 재현 절차가 필요하다는 점
- 기술 내용을 비전공 관계자에게 설명하는 발표 역량
