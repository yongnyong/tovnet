# 1. 중간발표까지 — AI 영상 분석 시스템 설계·개발

[프로젝트 전체 흐름](README.md) → **1단계** → [2. 중간발표 이후](02-after-interim.md)

기존 발표자료를 이 단계의 기준으로 사용합니다. 정확한 발표 날짜는 확정하지 않았습니다. 양호용이 전체 시스템의 설계·개발을 담당했으며, 중간발표까지의 구현과 이후 확장 과정을 나누어 설명합니다.

## 출발점: CCTV 영상을 분석하는 시스템 구현

CCTV 영상 입력, 모델 적용과 전처리, 영역 분할 결과 처리, 현장 영상 연결까지 AI 분석 파이프라인을 설계·개발했습니다. 기반 모델과 라이브러리를 활용하고 처리 방식별 성능을 비교해 중간발표 자료로 정리했습니다.

| 개발 영역 | 설계·구현 시 다룬 질문 |
|---|---|
| 입력 | 카메라 영상은 어떤 경로로 들어오는가? |
| 추론 | 모델에 맞는 입력 크기와 전처리는 무엇인가? |
| 출력 | 영역 마스크를 화면과 분석 결과로 어떻게 해석하는가? |
| 성능 | 처리 방식에 따라 지연시간·정확도·메모리가 어떻게 달라지는가? |
| 현장 연결 | 앱 영상과 서버의 직접 영상 접속이 같은 경로인가? |

## 당시 발표의 비교 기록

기존 자료에는 Tiling에서 Full Resolution 방식으로 바꾼 비교가 있습니다.

| 지표 | 기존 발표에 기록된 값 |
|---|---|
| 지연시간 | 1,481ms → 646ms |
| mIoU | 0.3534 → 0.3820 |
| VRAM | 6.33GB |

이는 **당시 벤치마크 기록**입니다. 이번 문서 갱신 때 재측정하지 않았으며, 2단계 v3 후보의 부유물 IoU와 평가 조건·지표가 다릅니다. 최신 운영 속도나 최신 모델 정확도로 재사용하지 않습니다.

## 현장 영상이 들어오기 위한 기반

같은 프로젝트의 현장 작업에서는 카메라·공유기·노트북 연결과 WEB/RTSP 접근 경로를 점검했습니다. 제조사 앱이 클라우드 경유로 영상을 보여주는 경우, 앱 접속 성공만으로 서버의 직접 접속이 정상이라고 판단할 수 없습니다.

카메라의 실제 내부 주소, 포트포워딩 대상, DHCP 할당 상태를 나눠 확인하고, 주소가 변경될 때 목적지가 어긋나는 문제를 예방하기 위한 예약·고정 주소 관리 절차를 정리했습니다. 이는 별도 AI 프로젝트가 아니라 이후 모니터링 파이프라인의 입력을 확보하는 현장 작업입니다. 현장 작업 날짜가 발표 이전이라고 단정하지 않고 기술적 맥락으로 함께 연결합니다.

## 다음 단계로 이어지는 질문

모델이 한 프레임을 분할하는 것과, 현장에서 지속적으로 관측하고 경보를 보여주는 것은 추가 구현이 필요합니다.

- 수면 반사·PTZ 이동·끊기는 영상에서 마스크와 비율을 어떻게 안정화할 것인가?
- 원시 측정과 화면 표시값을 어떻게 남기고 해석할 것인가?
- 부유물 증가를 미리 보여줄 수 있는가?
- 재학습이 면적·경보에 미치는 영향을 어떤 평가로 확인할 것인가?

이 질문에 대한 후속 작업을 [2. 중간발표 이후](02-after-interim.md)에서 이어갑니다.
